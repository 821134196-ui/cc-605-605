# 门店折扣码泄露封禁与订单追溯系统

连锁门店折扣码外泄后的应急处置系统：**立即停用受影响的码**，并**查清每笔已使用优惠的订单**。

- 后端：Go + Gin + GORM + SQLite（纯 Go 驱动，无需 C 工具链）
- 前端：Vue 3 + Vite，构建后嵌入 Go 二进制，**单进程**提供页面与 API
- 支付回执：本地模拟
- 金额：全程以「分」的整数存储与计算

## 一条命令启动

```bash
./run.sh          # 构建前端→编译→启动，访问 http://localhost:8080
./run.sh dev      # 开发模式：Vite 热更新 :5173 + Go API :8080
./run.sh test     # 后端并发测试(-race) + 真实 HTTP 端到端验证(30 项断言)
```

首次启动自动建表并写入种子数据（3 个商品、3 个批次、5 个码）。重置数据：删除 `data/app.db` 后重启。

## 业务规则如何落地

**批次**配置适用会员等级、适用商品、有效期、折扣（百分比/立减）与门槛。

- **码尾号展示**：码列表、订单、影响清单一律只回显 `****47FD` 形式尾号；`full_code` 字段标记 `json:"-"`，任何列表接口都拿不到完整码。发新码时完整码仅返回一次。
- **封禁**（可封整批或单码）：
  - **待付款订单**立即按封禁后的状态重新核价 → 优惠被剥离，按原价支付；订单追加一条 `BAN_STRIPPED` 核价历史。
  - **已付款订单**金额与优惠规则快照**原样冻结**，不追扣、不改写，自动进入**影响清单**供运营逐笔追溯（清单条目带支付回执上的原规则、原折扣、原实付、服务端核销时间、码尾号）。
- **订单详情**保留采用的优惠规则快照（批次、码尾号、折扣规则、门槛、适用会员/商品、适用金额、快照时间）与只追加的核价历史。
- **支付与封禁同时发生**：所有写操作经过同一把服务端写互斥，「读状态 → 核价 → 条件写库」是串行序列；以**服务端事务时刻**裁决：
  - 支付先入 → 核销成功、保留优惠，随后的封禁只把码标记为「已核销·后封禁」，订单进影响清单；
  - 封禁先入 → 支付时重新核价剥离折扣、按原价收款、不核销码。
  - 无论哪种结果，**一笔订单恰好一条回执、一个折扣金额**，订单金额与回执金额严格相等。
- **同一码并发核销只成功一次**：写互斥串行化 + 数据库条件更新
  `UPDATE codes SET status='redeemed' WHERE id=? AND status='active' AND banned_at IS NULL`
  双重保证；落败方收到 409（码已核销），不会出现两笔折扣。
- **重复支付回执幂等**：`payments.receipt_no` 唯一索引。同一回执号重复到达 → 返回原回执、标记 `idempotent_replay`、**不二次扣款、不落第二条记录**；回执号串到别的订单 → 409 冲突；回执金额与服务端应付不符 → 409 拒付且订单状态不变。
- **误封恢复**：仅当码**未核销**（redeemed 是终态）、所属批次未封禁、且**仍在有效期**才可恢复；已核销码任何情况下都不会重新开放，批次解封也不会重开它们。

## HTTP 接口

| 方法 路径 | 说明 |
| --- | --- |
| `GET /api/products` `/batches` `/codes?batch_id=` | 商品 / 批次 / 码（仅尾号） |
| `POST /api/batches/:id/ban` `/restore` `/codes` | 封批次 / 解封 / 发新码 |
| `POST /api/codes/:id/ban` `/restore` | 封单码 / 误封恢复（带规则校验） |
| `POST /api/quote` `/orders` | 仅核价 / 服务端核价并创建待付款订单 |
| `POST /api/orders/:id/requote` `/pay` | 重新核价 / 提交本地模拟支付回执 |
| `GET /api/orders` `/orders/:id` `/payments` | 订单列表 / 详情(规则快照+核价历史+回执) / 回执 |
| `GET /api/impact?batch_id=&code_id=` | 影响清单：已付款且优惠事后被封禁的订单 |

支付回执请求体：`{"receipt_no":"渠道回执号(可空)", "paid_amount": 分(可空)}`。留空回执号模拟自动出回执；金额留空表示渠道按服务端金额确认。

## 前端页面

- **核价与下单**：选会员/商品、输完整码，查看服务端核价结果与规则快照，可直接模拟支付。
- **批次与折扣码**：封批次/单码、误封恢复、发新码（完整码仅显示一次）。
- **订单与支付回执**：订单详情含规则快照、金额快照、核价历史、回执；可手动重新核价、模拟支付/重复回执/错误金额。
- **影响清单追溯**：受影响已付款订单汇总（笔数、优惠总额、实付总额）与每笔原优惠快照。
- **并发演练**：浏览器真实并发发起 ①同码 N 笔同时支付 ②支付×封禁多轮对撞 ③重复回执，实时显示裁决结果与一致性校验。

## 目录

```
cmd/server/      入口 + 前端 embed
internal/models  GORM 模型（金额/规则快照/核价历史/回执）
internal/pricing 纯函数核价（会员/商品/有效期/门槛判定，时间可注入）
internal/store   SQLite 打开、迁移、种子
internal/app     服务层（写互斥+事务+条件更新）、HTTP 路由、测试
frontend/        Vue 3 前端
scripts/e2e.sh   真实 HTTP 端到端验证（30 项断言）
```
